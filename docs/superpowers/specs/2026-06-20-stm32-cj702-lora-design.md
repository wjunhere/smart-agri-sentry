# STM32F103RCT6 + CJ-702 空气传感器采集与 LoRa 转发设计

## 1. 背景与目标

在 YB-MSA02-v1.1（STM32F103RCT6）开发板上，连接 CJ-702 空气传感器，采集 eCO2、eCH2O、TVOC、PM2.5、PM10、温度、湿度共 7 个环境量，每 60 秒计算一次算术平均值，并通过 USART3 连接的 LoRa 模块以自定义二进制帧格式发送出去。

## 2. 硬件接口

### 2.1 主控

- 板卡：YB-MSA02-v1.1
- MCU：STM32F103RCT6，256KB Flash，48KB SRAM，LQFP-64
- 主频：72MHz
- 供电：Type-C 5V → LDO 3.3V

### 2.2 CJ-702 空气传感器

- 接口：UART，仅 TXD 输出
- 波特率：9600 bps，8 数据位，无校验，1 停止位
- 供电：5V
- 输出周期：每 2 秒一帧（0.5Hz）
- 连接：STM32 USART2 PA3（RX）← 传感器 TXD；PA2（TX）可悬空或复用为 GPIO

### 2.3 LoRa 模块

- 型号：E22-400T30S（参考现有 `example/lora` 驱动）
- 连接：STM32 USART3 PB10（TX）→ LoRa RX；PB11（RX）← LoRa TX
- 工作模式：透传模式（M0=0, M1=0）

## 3. 软件架构

采用 **定时器驱动状态机（方案 B）**，不引入 RTOS。

```
USART2 RX 中断 + 环形缓冲区
        │
        ▼
  cj702_parser （帧头/校验/解析）
        │
        ▼
  aggregator （60 秒算术平均池）
        │
        ▼
  lora_frame （自定义二进制帧打包 + CRC8）
        │
        ▼
  lora_tx （USART3 阻塞发送）
        ▲
  TIM2 1 秒 tick
        │
  app_fsm （SAMPLE → ACCUMULATE → TX → WAIT）
```

## 4. 模块划分

| 模块 | 文件 | 职责 |
|---|---|---|
| cj702_parser | `cj702.c/h` | 解析 17 字节原始帧，校验和检查，解出 7 个物理量 |
| aggregator | `aggregator.c/h` | 60 秒累加，计算算术平均；管理有效样本计数 |
| lora_frame | `lora_frame.c/h` | 按自定义二进制协议打包 payload，计算 CRC8 |
| lora_tx | `lora_tx.c/h` | 通过 USART3 发送数据 |
| app_fsm | `app_fsm.c/h` | 1 秒 tick 状态机：SAMPLE → ACCUMULATE → TX → WAIT |
| status_led | `status_led.c/h` | RGB 灯状态指示（可选） |

## 5. 数据流与帧格式

### 5.1 CJ-702 原始帧（17 字节）

| 字节 | 名称 | 说明 |
|---|---|---|
| B1 | 帧头 1 | 0x3C |
| B2 | 帧头 2 | 0x02 |
| B3~B4 | eCO2 | 高/低字节 |
| B5~B6 | eCH2O | 高/低字节 |
| B7~B8 | TVOC | 高/低字节 |
| B9~B10 | PM2.5 | 高/低字节 |
| B11~B12 | PM10 | 高/低字节 |
| B13 | Temperature 整数部分 | bit7 为符号位 |
| B14 | Temperature 小数部分 | |
| B15 | Humidity 整数部分 | |
| B16 | Humidity 小数部分 | |
| B17 | 校验和 | B1~B16 累加低 8 位 |

温度计算：
- B13 bit7 = 1 表示负温，实际温度 = -(B13 & 0x7F) - B14 / 100.0
- B13 bit7 = 0 表示正温，实际温度 = B13 + B14 / 100.0

### 5.2 STM32 → LoRa 自定义二进制帧

帧结构为变长格式，由帧头、设备 ID、消息类型、长度、payload、CRC8 组成：

| 字节 | 字段 | 说明 |
|---|---|---|
| 0~1 | 帧头 | 0xAA 0x55 |
| 2 | 设备 ID | 默认 0x01 |
| 3 | 消息类型 | 0x01=传感器数据，0xFF=错误状态 |
| 4 | 长度 | payload 长度 N |
| 5 ~ 5+N-1 | payload | N 字节数据 |
| 5+N | CRC8 | 帧头到 payload 的 CRC8 |

- 传感器数据帧总长度：20 字节（payload 14 字节）
- 错误状态帧总长度：7 字节（payload 1 字节）

CRC8 采用 CRC-8/MAXIM，多项式 `0x31`，初始值 `0x00`，覆盖范围：帧头 → payload 全部字节。

#### 传感器数据 payload（14 字节）

| 字节 | 字段 | 类型 | 单位 |
|---|---|---|---|
| 0~1 | co2 | uint16_t | ppm |
| 2~3 | hcho | uint16_t | 原始值 |
| 4~5 | tvoc | uint16_t | ppb |
| 6~7 | pm25 | uint16_t | μg/m³ |
| 8~9 | pm10 | uint16_t | μg/m³ |
| 10~11 | temp | int16_t | 0.01 °C |
| 12~13 | humidity | uint16_t | 0.01 %RH |

#### 错误状态 payload（1 字节）

| 值 | 含义 |
|---|---|
| 0x01 | 传感器通信超时 |
| 0x02 | 数据不完整 / 连续校验失败 |

## 6. 状态机

TIM2 每秒产生一次 tick，驱动主状态机：

- **USART2 RX 中断**：异步接收 CJ-702 数据，收到完整且校验通过的帧后，直接调用 `aggregator_add()` 加入平均池。
- **1 秒 tick**：
  1. **ACCUMULATE**：持续累加，维护 60 秒窗口计数。
  2. **TX**：60 秒到达时，根据有效样本数决定发送传感器数据帧或错误帧；然后清空平均池。
  3. **WAIT**：等待下一秒 tick，回到 ACCUMULATE。

## 7. 错误处理

| 场景 | 行为 |
|---|---|
| 单帧校验失败 | 丢弃，不加入平均池 |
| 帧头不对/长度不足 | 丢弃，等待下一帧 |
| 60 秒内有效样本 ≥ 10 | 计算平均值，发送传感器数据帧 |
| 60 秒内有效样本 < 10 | 发送“数据不完整”错误帧（0x02） |
| 连续 60 秒无任何有效帧 | 发送“传感器通信超时”错误帧（0x01），LED 切到异常状态 |
| LoRa 发送超时 | 记录错误，下一周期再试，不阻塞系统 |

## 8. 后续扩展预留

后续加入叶面湿度、土壤传感器时，按相同模式新增：
- 独立 parser 模块
- aggregator 中新增对应字段
- LoRa payload 中新增字段
- 消息类型不变或新增子类型

由于采用模块化单线程状态机，新增传感器不会影响现有任务调度逻辑。

## 9. 测试计划

### 9.1 单元测试

- 构造合法 CJ-702 帧，验证 parser 解出的 7 个物理量正确。
- 构造校验和错误、帧头错误的帧，验证被丢弃。
- 构造 30 帧样本，验证 aggregator 平均值计算正确。

### 9.2 集成测试

- 连接 CJ-702，验证 USART2 中断接收正常。
- 用逻辑分析仪或串口助手抓取 USART3 输出，验证自定义帧格式。
- 断开传感器，验证 60 秒后发送错误状态帧。

### 9.3 长期测试

- 连续运行 10 分钟以上，观察数据稳定性和内存使用。
