# 网页巡航历史读取设计

## 目标

在 RDK 板端长期保存完整巡航批次，使网页刷新后仍可在顶部设置按钮中按批次、日期、作物和病害读取历史。每个批次包含视觉诊断、融合结果、农艺建议、预警趋势与最多 10 张检测截图。

## 批次定义与保留

- 一次由 `AUTO` 启动至完成或手动结束的过程为一个批次。
- 中途多次停靠、识别植株均归入该批次。
- 历史根目录为 `/home/sunrise/.local/state/sentry/cruise_history/`。
- 每批保留最多 10 张检测截图；后续截图不写入并记录计数。
- 同时保留最近 90 天和最近 30 个批次；超过任一限制时删除最旧批次及其截图。
- 完整批次归档仅适用于本功能部署后的新巡航；既有风险 JSONL 不回填为完整批次。

## 数据格式

每批使用一个原子写入的 JSON 文件与独立图片目录：

```text
cruise_history/
  batches/<batch-id>.json
  images/<batch-id>/<seq>.jpg
```

JSON 包含：批次 ID、开始/结束时间、结束原因、作物类型、检测记录、疾病分类、融合结果、农艺建议、预警事件、风险点和截图相对路径。每条记录携带时间戳，方便日期、作物和病害筛选。

## 网页交互

在现有顶部“参数设置”弹窗中增加“巡航历史”区域：

- 批次数选择：1–30，默认 10。
- 日期快捷选择：今天、近 3 天、近 7 天；以及自定义开始/结束日期。
- 作物和病害下拉筛选，默认全部。
- “读取历史”将匹配批次回放至融合决策链、预警趋势、农艺建议及历史列表。
- “清空当前网页显示”仅清空浏览器内存，不请求删除板端数据。
- “删除板端历史”为独立危险操作，可按当前筛选范围或全部删除，必须二次确认。

网页刷新后不自动混入旧数据；用户以默认“近 7 天、最近 10 批”筛选点击读取，避免历史结果与实时巡航结果混淆。

## API

- `GET /api/history/batches`：接受 `limit`、日期范围、`crop_type`、`disease`，返回批次摘要与可回放事件。
- `GET /api/history/batches/<id>/snapshot/<seq>`：返回已归档截图。
- `DELETE /api/history/batches`：接受 `scope=all|filtered` 与筛选条件；请求必须提供明确确认字段，否则拒绝。

API 返回路径均由网页服务生成，不暴露板端绝对文件路径。

## 错误处理

- 单个批次写入失败时记录错误，不影响正在运行的巡航。
- 图片写入失败时保留其他元数据并标记该截图不可用。
- 历史读取或删除失败时网页显示错误提示，保留当前实时面板数据。
- 删除请求只删除历史根目录内经解析验证的批次，不接受用户提供的文件路径。

## 验收

1. 完成一次含植株检测的巡航后，刷新网页可读取该批次及截图。
2. 批次、日期、作物、病害筛选返回正确结果。
3. 第 11 张截图不会归档；第 31 批或超过 90 天的最旧批次被清理。
4. 网页“清空当前显示”不删除板端数据。
5. 板端删除需要二次确认，且仅影响匹配的归档批次。
